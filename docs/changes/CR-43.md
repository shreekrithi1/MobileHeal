## Design notes

- New required input “Restaurant Name” is added below existing fields with a text keyboard. Users missing it see the alert banner and the field is highlighted in red until filled.
- New required input “Menu Item” is added below existing fields with a text keyboard. Users missing it see the alert banner and the field is highlighted in red until filled.
- New required input “Quantity” is added below existing fields with a text keyboard. Users missing it see the alert banner and the field is highlighted in red until filled.
- New required input “Fulfillment Method” is added below existing fields with a text keyboard. Users missing it see the alert banner and the field is highlighted in red until filled.
- New optional input “Table Number” is available; no alert is raised if left blank.
- New optional input “Special Instructions” is available; no alert is raised if left blank.
- New optional input “Contact Phone” is available; no alert is raised if left blank.
- “Date of Birth” is no longer a rule; the app stops prompting for it (stored values are kept).
- “Town” is no longer a rule; the app stops prompting for it (stored values are kept).
- New navigation: after a successful save the app shows a Success screen (“Order placed”) with a “Back to profile” action. If required fields are missing, the user stays on the profile and sees the alert banner instead.
- Colour changes are applied live over the WebSocket; no app release is required.
- ⚠ Save button contrast is 3.91:1 (AA Large). WCAG AA needs 4.5:1 for normal text — consider a darker/lighter text colour.
- DataWatchdog: once live, 4 existing profiles will be missing restaurant name, 4 existing profiles will be missing menu item, 4 existing profiles will be missing quantity, 4 existing profiles will be missing fulfillment method, 2 existing profiles will be missing name — those users get an in-app notification to complete it, and the team is alerted.
