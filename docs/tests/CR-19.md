# Test cases for CR-19

_Plain-English test cases. Steps marked 🤖 can run automatically in the preview._

## 1. Happy path: Save with valid Name and Email; removed fields not shown

**Priority:** High  
**Objective:** Ensure user can save profile with required fields only; removed fields (Zip, Phone Number, Nationality) are not visible; UI color/label correct; stays on Profile and shows success toast.  
**Preconditions:** User is on the Profile screen.  
**Test data:** Name = `Ava Johnson`, Email = `ava.johnson@example.com`

| # | Step | Expected result |
|---|---|---|
| 1 | Verify that fields Zip, Phone Number, and Nationality are not present on the screen. | Zip, Phone Number, and Nationality inputs (and labels) are not visible anywhere on the Profile screen. |
| 2 | 🤖 Verify the primary button label and color. | Primary button label is 'Save changes' and the color matches #079455. |
| 3 | Enter a valid Name and Email. | Name and Email fields display the entered values. |
| 4 | 🤖 Tap the primary Save button. | App attempts to save and stays on the Profile screen. |
| 5 | 🤖 Observe the success feedback. | A toast/banner appears indicating success (e.g., 'Changes saved successfully'). |

## 2. Negative: Submit with both Name and Email empty shows required banner (only those fields)

**Priority:** High  
**Objective:** Ensure validation only applies to Name and Email and banner lists just those; removed fields are not referenced.  
**Preconditions:** User is on the Profile screen with Name and Email empty.  

| # | Step | Expected result |
|---|---|---|
| 1 | Ensure Name and Email are empty. | Both fields show no text. |
| 2 | 🤖 Tap the primary Save button. | Validation triggers and app stays on Profile screen. |
| 3 | 🤖 Check the alert banner for missing fields. | Banner is visible and mentions 'Name' as required. |
| 4 | 🤖 Check the alert banner also mentions Email. | Banner mentions 'Email' as required. |
| 5 | Verify banner does not mention removed fields. | Banner does NOT mention Zip, Phone Number, or Nationality. |

## 3. Negative: Only Name filled; Email empty shows banner only for Email

**Priority:** Medium  
**Objective:** Ensure partial input triggers banner only for the specific missing required field (Email).  
**Preconditions:** User is on the Profile screen.  
**Test data:** Name = `Chris Lee`

| # | Step | Expected result |
|---|---|---|

**Priority:** Low  
**Objective:** Ensure long inputs are handled gracefully and saving still works or shows clear validation.  
**Preconditions:** User is on the Profile screen.  
**Test data:** Long Name = `Alexandria-Cassandra Maximilianus de la Cruz Montgomery the Third`, Long Email = `very.long.alias.with.many.segments.and.labels.including.subdomains+tagging.for.testing.purposes@example-very-long-domain-name-that-still-should-be-valid.com`

| # | Step | Expected result |
|---|---|---|
| 1 | Enter the very long Name and Email into their respective fields. | Text is accepted without layout break (truncation/scrolling acceptable). |
| 2 | 🤖 Tap the primary Save button. | Either saves successfully and stays on Profile, or shows clear validation without app crash. |
| 3 | 🤖 Observe feedback after save attempt. | If saved, success toast appears (e.g., contains 'Saved'). If not saved, a validation banner appears explaining the issue (not referencing removed fields). |
